## 0. 一句话定义

一个嵌在知乎问题页下的互动内容。玩家用二十分钟走完一段被压缩的人生，在每一次取舍中看见这个议题的正反两面，最后形成自己的观点。

---

## 1. 产品定位与设计原则

### 1.1 这不是一款游戏

它是**议题表达工具**，不是娱乐产品。玩家是刷知乎时点进来的，不是专门来玩的。所有设计决策在"更好玩"和"更少负担"之间冲突时，一律选后者。

目标是让玩家认识到一件事情好的一面和坏的一面，最后形成自己的观点，让自己的逻辑自洽起来。

### 1.2 核心理念：无论怎么选，都会失去一些东西

取舍是双向的。**玩家得到他想要的东西，才会遇到困境。**

> 我为了赚钱来到大城市，我确实赚到钱了，代价是陪伴家人的时间不够。

正反两面都必须让玩家看到。这条理念约束了后面所有的机制设计，尤其是结算系统（见 4.3）。

### 1.3 三条不可违背的原则

**原则一：玩家负担一票否决。** 任何要求玩家产出文字的设计，默认否决。任何一次性抛出大段文字的呈现，默认否决。

**原则二：不追求精准命中，追求触动大部分人。** 一部好电影的编剧不会去猜每个观众内心最柔软的地方在哪，但好作品能触动大多数人。我们走同样的路线。

**原则三：用具体场景代替抽象论点。** 这是原则二唯一的实现方式。

> 不要说"不生小孩没人养老"。
> 要说"下了班以后，万家灯火没有一盏是为你而留"；"人到中年，曾经的兄弟在朋友圈晒自己小孩肉嘟嘟的"；"你再约他出来玩，他说不行，要接小孩放学"。

### 1.4 已否决方案清单

以下方案讨论过并明确否决，不要在后续设计中重新引入：

| 方案 | 否决理由 |
| --- | --- |
| 蒸馏知乎答主，反推其人生矛盾 | 几篇回答反推不出一个人的人生；多人对同一事物的分析已足够全面客观；涉嫌侵犯隐私 |
| 回档机制 + 强制提交"为什么回档"的报告 | 严重负反馈。"我玩得正高兴呢，你突然跳一行字出来让我写篇小作文" |
| 追求个性化命中玩家内心的隐藏矛盾 | 玩家在游戏里的选择未必等于现实选择（会存档乱点）；要求全身心代入，负担过重 |
| 后悔事件的自动归因 | 线性流程难以自动归因，改为轻量化的玩家主动填写（见 7.2） |

## 2. 内容层：两层结构

内容侧的全部产出就是这两种卡。程序侧只认这两个 schema。

### 2.1 母题卡（一局人生的剧本）

一个知乎议题对应一张母题卡。

```json
{
  "母题ID": "big-city-or-hometown",
  "母题名": "毕业后该去大城市还是回家乡",
  "来源问题": "https://www.zhihu.com/question/xxx",
  "时代背景": "2020 年代，二线城市房价与一线薪资的剪刀差",
  "入场年龄": 22,
  "人生终点": 75,
  "总回合数": 7,
  "立场选项": [
    { "立场ID": "big-city", "文案": "去大城市闯一闯", "初始flags": ["离乡"] },
    { "立场ID": "hometown", "文案": "回家乡安稳过", "初始flags": ["守土"] }
  ],
  "身份设定": [
    {
      "身份ID": "985-only-child",
      "文案": "985 本科，独生子，父母在小城有些人脉",
      "初始长期状态": { "财富": 20, "健康": 80, "心力": 70, "声望": 45 },
      "初始关系": [
        { "角色": "父亲", "亲密度": 65, "态度": "希望你回来考公" },
        { "角色": "母亲", "亲密度": 75, "态度": "嘴上支持，心里舍不得" }
      ]
    }
  ],
  "标签白名单": ["职业", "家庭", "婚恋", "养老", "城乡差距"],
  "出题约束": "每回合的决策必须让玩家在'个人发展'和'亲情陪伴'之间做实质取舍，不得出现无代价的选项",
  "结局评价维度": ["世俗成就", "亲密关系", "内心安宁"]
}
```

**关键字段说明：**

- `入场年龄` / `人生终点`：因为时间跨度是动态的（见 4.5），母题卡**不能预写"每回合对应什么年龄段"**，只能给出起止。
- `立场选项`：定世界线起点，对应入口第一步。
- `身份设定`：定起始状态栏数值，对应入口第二步。
- `出题约束`：决策 Agent 的出题规则。内容侧写的不是选项列表，是**出题规则**。

### 2.2 困境卡（素材库）

```json
{
  "困境ID": "father-illness",
  "困境名": "父亲确诊重病",
  "触发条件": {
    "年龄区间": [35, 55],
    "状态阈值": { "财富": "<60" },
    "必需flags": ["父母健在"],
    "排斥flags": []
  },
  "所需标签": ["家庭", "养老"],
  "具体场景": "医生把你叫到走廊，说了个数字。你打开手机银行，看着余额，第一次觉得'再攒两年'这句话很轻。",
  "解决路径提示": "掏积蓄治病 / 把父母接到身边 / 请护工远程照料 / 拖着不管",
  "困境权重": 20,
  "未解决后果": {
    "长期状态伤疤": { "心力": -15 },
    "新增flag": "父亲病逝",
    "关系影响": [{ "角色": "母亲", "亲密度": -20 }]
  }
}
```

### 2.3 素材来源

**从一个知乎问题下的多个高赞回答聚合**，提取正反两面的论点和具体场景，加工成困境卡。不针对单一答主做画像。

选题标准：能分解为目标和重大决策，能转化为人生故事，且社区里有足量的正反两方观点。

## 4. 核心玩法循环

### 4.0 入口（回合开始前）

两步，内容由母题卡定义：

1. **选立场** — 定世界线起点
2. **选身份** — 定起始状态栏与初始关系

### 4.1 回合流程（共 7 回合）

每回合六步，由**代码状态机驱动**：

| 步骤 | 内容 | 执行者 |
| --- | --- | --- |
| 1. 承上 | 即时状态并入长期状态，生成事件卡与角色卡变化 | 叙事 Agent + 关系 Agent |
| 2. 生成困境 | 读长期状态、年龄、flags，从困境库选卡并具体化 | 困境 Agent |
| 3. 决策 | 出 3 个决策选项，玩家选定，即本回合目标 | 决策 Agent + 玩家 |
| 4. 行动 | 玩家分配并执行行动点 | 玩家 + 行动裁定 Agent |
| 5. 结算 | 概率计算，判定四档 | 纯代码 |
| 6. 时间推进 | 按决策的时间跨度推进年龄 | 纯代码 |

**困境必须在决策之前生成。** 玩家带着一个已知的麻烦去做人生决策，决策才有张力；反过来先定目标再丢困境，困境就退化成了随机干扰项。

### 4.2 决策与行动的分工

| 概念 | 管什么 | 可逆性 |
| --- | --- | --- |
| 决策（= 本回合目标） | 世界线走哪条分支、时间跨度多长 | 一次性，不可逆 |
| 行动 | 目标达成的质量、即时状态、困境解决度 | 回合内可累积 |
| 困境 | 对目标概率的负面修正 | 可被行动化解 |

**决策决定"你走上了哪条路"，结算只决定"你在这条路上走得好不好"。** 玩家决策"娶妻"，世界线就进入已婚支线；结算失败不等于没结婚，而是结成了一段将来会拖累长期状态的婚姻。**结算失败不回滚世界线分支。**

### 4.3 结算：四档，但四档只决定"得到多少"

**这里是全篇最容易做错的地方。** 四档不是"你表现得好不好"的评分，因为那和 1.2 的核心理念直接冲突——玩家连拿三个大成功，"无论怎么选都会失去东西"就当场垮掉。

**四档只决定你得到了多少。代价是恒定必付的，只是形态不同。**

| 档位 | 产出 |
| --- | --- |
| 大成功 | 拿到目标 + 长期状态额外增益，代价是你预料之中的那个 |
| 成功 | 拿到目标，代价如期而至 |
| 勉强 | 拿到目标，但代价比你以为的更重（额外扣一项长期状态，或困境原封不动带进下回合） |
| 失败 | 没拿到目标，代价照付，困境固化为长期状态上的伤疤 |

"勉强"必须是"达成了，但付了代价"，不能是"没达成，但安慰你"。否则它只是一档更软的失败，四档就白分了。

### 4.4 概率与判定

**概率构成：**

```
P = P基线 + 长期状态修正 + 行动修正 − 困境debuff
```

| 项 | 范围 | 说明 |
| --- | --- | --- |
| P基线 | 25 ~ 60 | 由决策 Agent 随选项一起给出 |
| 长期状态修正 | ±15 | 代码按相关维度计算 |
| 行动修正 | 单点 −5 ~ +12 | 由行动裁定 Agent 给出，可为负 |
| 困境 debuff | −20 ~ 0 | `−困境权重 × (1 − 解决度/100)` |

最终 clamp 到 `[5, 95]`。

**平衡约束（调参时的红线）：行动修正的总量必须大于状态修正加困境 debuff 的合力，但不足以单独翻盘。** 小于合力，玩家会觉得这回合怎么努力都没用；大到能单独翻盘，长期状态和困境就成了摆设。

**判定：** 摇 `R = d100`

```
R ≤ P − 25        → 大成功
P − 25 < R ≤ P    → 成功
P < R ≤ P + 25    → 勉强
R > P + 25        → 失败
```

固定尾巴：`R ≤ 5` 无条件大成功，`R ≥ 96` 无条件失败。再稳的局也有意外，再烂的局也有奇迹。

带宽 25 是**唯一的调参旋钮**：收窄趋近二元，放宽多中间态。

**概率对玩家可见**，但用模糊档位而非数字：`很有希望 / 有戏 / 悬 / 基本没戏`。玩家感知不到行动在推动概率，博弈就不存在了。

### 4.5 时间推进

时间跨度由决策决定（模型给出），但**必须由代码约束区间**，否则模型会在第三回合就把玩家推到 70 岁。

```
剩余年数 = 人生终点 − 当前年龄
剩余回合 = 总回合 − 当前回合
允许区间 = [3, min(15, 剩余年数 − 3 × (剩余回合 − 1))]
```

最后一回合强制推进到人生终点收尾。

因此**困境卡的触发条件按年龄，不按回合号**。

### 4.6 行动点：全局预算

**一辈子总共 14 点 = 每回合保底 1 点 × 7 + 自由池 7 点。** 玩家自己决定把自由池投在哪些人生阶段。

这不只是为了压缩交互次数（从 28 次降到 21 次以内）。更重要的是，**把行动点砸在事业上，就没得砸在家庭上**——行动点本身成为稀缺资源，"必有代价"这条立意在玩家分配精力的那一刻就已经生效，不必等到结算才兑现。

行动输入形态：**AI 给 3 个建议选项 + 一个自由输入框。**

### 4.7 困境解决度

困境是 0–100 的连续解决度，不是二元的解决/未解决。行动可以部分推进，debuff 按解决度线性给。

做成连续值是因为：三点行动要在"推目标"和"解困境"之间分配，这才是这套机制真正的张力来源。如果困境是二元的，玩家算一下就知道要么全力解、要么完全不管，中间的犹豫就没了。

### 4.8 即时状态如何折算进长期状态

结算时折算，且受档位影响。**注意方向不对称：**

- **正向增益**按档位系数缩放：大成功 ×1.5、成功 ×1.0、勉强 ×0.5、失败 ×0.2
- **负向代价全额结算，不缩放**

如果负向也乘系数，会出现"失败反而少扣"的荒谬结果。

## 5. Agent 架构

### 5.1 六个 Agent

| Agent | 职责 | 一局调用次数 | 建议模型档位 |
| --- | --- | --- | --- |
| 叙事 Agent | 承上，把状态变化翻译成事件卡 | 14 | 快 |
| 困境 Agent | 选困境卡并具体化为当前情境 | 7 | 强 |
| 决策 Agent | 出 3 个决策选项，含 P基线与时间跨度 | 7 | 强 |
| 行动裁定 Agent | 判定每次行动的效果 | ≤14 | 快 |
| 关系网络 Agent | 维护角色的亲密度与态度变化 | 7 | 快 |
| 人生卡片 Agent | 终局生成卡片文案 | 1 | 强 |

一局五十次上下的 LLM 调用。行动裁定和叙事占了大头且玩家在等，用快模型；困境和决策一回合才一次、质量更重要，用强模型。

### 5.2 编排层用代码，不用 Agent

回合流程是完全确定的六步，用状态机驱动，比让 orchestrator agent 决定"下一步该干什么"可靠得多也便宜得多。**多 Agent 指的是多个各司其职的专家 Agent，不是让它们自己商量流程。**

### 5.3 数值主权

**所有数值由 Agent 提议，由代码裁决和落库。Agent 不持有状态。** 否则几个回合后数值必然漂移。

### 5.4 输出契约

Agent 的输出必须是结构化的，**不能是一段散文**——因为呈现层是卡片，不是文章。

**行动裁定 Agent：**

```json
{
  "事件卡": [
    { "标题": "首付凑齐了", "摘要": "掏空六个钱包，你在三十岁生日前签了字。", "图标": "house" }
  ],
  "角色卡变化": [
    { "角色": "母亲", "亲密度delta": 15, "新态度": "她把房本照片发到了老家的家族群" },
    { "角色": "妻子", "亲密度delta": -8, "新态度": "婚礼的预算被砍掉了一半" }
  ],
  "即时状态delta": { "精力": -15, "现金流": -40 },
  "目标概率修正": 8,
  "困境解决度推进": 25,
  "新增flag": []
}
```

**决策 Agent：** 每个选项必须带上 `P基线`、`时间跨度`、`会种下的flags`、`明示的代价`。否则代码拿到"辞职创业"四个字，不知道基础成功率该给多少。

```json
{
  "选项": [
    {
      "文案": "跳槽去更卷但给股票的公司",
      "P基线": 40,
      "时间跨度": 8,
      "新增flags": ["高强度工作"],
      "明示代价": "接下来这些年，你大概率赶不上孩子的家长会"
    }
  ]
}
```

`明示代价` 是理念 1.2 的落地点：**在玩家做选择的那一刻就把代价说出来**，不藏到结算之后。

### 5.5 一致性策略（Demo 阶段）

Demo 阶段**不做 flag 硬校验**，只靠 prompt 里塞事实底稿。两个必须做的便宜措施：

1. `flags` 与 `关系网络` 以 JSON 原样注入每个 Agent 的 system prompt，不让模型从自然语言里推断"他好像结婚了"。
2. 每回合结算后由代码往底稿追加一条**不可变事实**（如"第 3 回合，父亲病逝"），永远置顶。

喂给 Agent 的**不是历史全文**，而是压缩后的状态栏 + flags + 关系网络 + 最近两回合摘要。上下文恒定大小，不随回合增长。

**已知风险：** 第 5 到 7 回合大概率出现事实矛盾。演示时若只跑前三四回合基本碰不到；要完整跑七回合，要么接受偶尔穿帮，要么后续补 flag 硬校验。

### 6.2 顶部状态栏

长期状态四条，用条形而非数字，降低认知负担。右侧 `[关系 ▸]` 点击展开**关系星图**。

### 6.3 关系星图（点击展开）

角色为节点，玩家在中心。**亲密度映射为距离和亮度**——疏远的人飘在外围、发暗；去世的角色变成灰色残影但不消失。点击节点看该角色的完整轨迹。

这是减负设计：不给玩家一大段文字，而是一张星图，哪里亮了哪里暗了一目了然，再配简短摘要。

### 6.4 人生事件树（类 git 树）

主干是玩家走过的路，每个决策点分叉。**未选的分支用虚线灰显，标注那条路的名字。**

这个设计直接服务于产品目的——**让玩家看见他这次选择舍弃了什么**。舍弃不需要用文字讲，画出来就行。

### 6.5 事件卡区

主区右侧。完成抉择后，事件卡和角色卡逐张出现，让玩家快速了解上次抉择到现在发生了什么，**不至于被一大片文字糊脸**。

### 6.6 结局呈现

电影滚动字幕形式，配 TTS 旁白朗读，进一步降低阅读负担。

## 7. 终局系统

### 7.1 人生卡片

游戏结局生成，汇流至社区展示。包含：

- **重大决策**：从事件树主干直接取
- **成就**：长期状态与关系网络的高位项
- **你放弃的那些路**：从事件树的未选分支直接取

第三项是**确定性可知的**——放弃了什么，就是未选的决策选项，不需要任何归因逻辑。这是砍掉自动归因之后仍然能自动生成的部分。

### 7.2 主观填答

只有真正主观的部分才需要玩家填，比如"这一生最后悔的事"。

**必须做成轻量的**：给几个从事件树生成的预设选项让玩家点选，允许但不强制补充文字，整个环节可跳过。

原则 1.1 说任何要求玩家产出文字的设计默认否决。这里之所以放行，是因为它在游戏结束之后、是自愿的、且有社区展示的回报。但一旦它变成必答题，就该砍掉。

## 8. 分工与排期

### 8.1 并行的前提

**先冻结第 3 节的状态对象和第 5.4 节的 Agent 输出契约。** 契约锁死后两边才能真并行，否则一个人调 prompt、一个人写结算逻辑，最后对不上字段。

### 8.2 分工

| 内容侧 | 程序侧 |
| --- | --- |
| 敲定选题，产出第一张母题卡 | 状态机与回合流程 |
| 从知乎回答聚合出困境卡库 | 概率结算与数值系统（4.4 / 4.8） |
| 六个 Agent 的 prompt | Agent 调用层与上下文构造（5.5） |
| 出题约束与结局评价维度 | 前端三块布局（6.1） |

### 8.3 Demo 目标

本周内跑通一个可演示版本。**建议 Demo 只跑前 3 回合**，避开 5.5 里说的一致性风险。
